# v4 评测集 Datasheet

## 基本信息

- 版本：v4（P1 设计稿），协议 `v4-2026-11-04`，seed `20261104`，as_of `2026-11-04`；
- 规模：40 正向 + 8 负向；交付要求 8 人/场景；
- 生成命令：`python eval/build_v4_scenarios.py`；
- 场景文件：`eval/frozen/v4/scenarios.json`。

## 数据来源

- 供应池：`deploy/mysql/sql/base/01-paringbot.sql`（900 成员、900 偏好、841 已审核通过）；
- 申请人档案/偏好：由 `build_v4_scenarios.py` 按固定模板从格子统计量生成（不复制种子成员文本）；
- 不含真实用户隐私数据；所有 profile 为合成评测数据。

## 构造与污染控制

- 场景/标签/运行分离：eval profile 只有 base 数据，不补供给；
- 确定性采样：seed 固定，重复构建字节一致；
- 防污染：申请人文本来自固定模板，不复用 v3 申请人；对照候选不进入生产池；
- 冻结：scenarios.json 的 sha256 记录在 `MANIFEST.json`；标签完成后单独冻结。

## 已知限制

- 性别覆盖 19/21（目标 20/20），因种子数据中高/中容量层女性偏多；
- 标签尚未生成，**当前不能用于质量结论**；
- 门店覆盖 16/20（其余门店无满足容量层的格子）；
- 档案为合成数据，存在“兴趣标签 vs has_pet”矛盾（v3 面板已发现），v4 生成时未修复；
- 未包含真实用户行为/在线反馈。

## 预期用途

- 评测方法验证（pass^k、CI、judge 校准）；
- 面试展示“评测集如何设计、如何防污染、如何分层”；
- 不作为生产质量证书。

## 维护

- 修改生成器必须重跑 `--check` 并更新 MANIFEST；
- 标签变更必须单独版本化，禁止直接改 gold；
- v4 标签未完成前，CI 只校验场景文件形状，不接门禁。
