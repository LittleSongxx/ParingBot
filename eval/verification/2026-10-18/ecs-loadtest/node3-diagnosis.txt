# node3 性能排查（2026-10-18）
# 400 VU 30s，三节点 product 请求增量近似相等（各约 1913）；同一份 product/gateway JAR、同一 Java 17。

node1 product/gateway CPU: 96.5% / 57.0%（8 核）
node2 product/gateway CPU: 96.6% / 50.0%（4 核）
node3 product/gateway CPU: 247.9% / 179.2%（4 核）

node3 空闲单次 GET /product/loadCategory:
  node2: 8.2–10.4ms
  node3: 15.2–33.8ms

直连 MySQL sys_product_property count:
  node2: 2–4ms
  node3: 3–4ms

Redis PING:
  node2: 2–3ms
  node3: 3–8ms

Hikari（400 VU 采样）:
  node2 active max 1, acquire max 18.55ms, pending 0
  node3 active max 5, acquire max 215.81ms, usage max 167ms, pending 0

结论：请求分布基本相等，但 node3 在相同请求量下大约消耗 2–2.5 倍 CPU；DB/Redis 网络延迟只比 node2 高 1–4ms，不能解释全部差异。发现 /product/loadCategory 每个请求都会再查一次分类表并把快照写 Redis（仓库中没有该 Redis 快照的消费者）。已从公开读路径移除该写入，保留管理端写路径刷新；该修复待下一轮部署验证。
