# 批次一：P0 交易一致性修复（孤儿订单 / 库存虚增 / 对账死路径 / quote claim / 幂等独立事务 / 查询索引）

- 日期：2026-10-14（Asia/Shanghai）
- 关联 ADR：[0018](../../adr/0018-order-consistency-fixes.md)
- 代码版本：本批次提交（`git log` 见 commit `fix(order): 批次一 P0 一致性修复…`）
- 定位：**计划内修复**——源于 2026-10-14 全量代码评审（4 项高危结论均亲读源码核实）。

## 需求

修复评审确认的 P0/P1 交易一致性与可运维性缺口，对齐行业主流做法（消息与业务原子化、
账本只增不删、对账兜底真实可用、互斥先于副作用、幂等留痕独立提交），并为订单域补齐
核心查询索引。本轮为七批次修复计划的第一批，后续批次：结构重构与短事务化、退款还券、
观测链路、安全加固、可靠性清理、测试补齐。

## 具体变更

| # | 缺陷（评审结论） | 修复 | 关键源码 |
| --- | --- | --- | --- |
| 1 | Phase 4 失败留下无支付意图、无关单消息的永久孤儿订单（注释与实现不符） | 延时关单消息移入 Phase 3 短事务（Outbox 与订单同事务落库）；修正注释 | `OrderInfoServiceImpl.createOrder`（Phase 3 块内 sendAfterCommit 循环） |
| 2 | 孤儿单关闭时回补从未扣减的库存 → 库存虚增 | `restoreOrderStock` 前置校验 `order-deduct:` 账本存在；移除 `releaseOrderDeductKey`，账本只增不删 | `SkuStockService.restoreOrderStock`、`StockChangeRecordMapper`（删 deleteByBusinessKey） |
| 3 | 支付轮询对账死路径（`markPayTradeInitiated` 无生产调用方，轮询永远空转） | 按 `order_status=0 AND order_time<now-180s` 分页轮询直接查渠道；单笔失败不断批；删除 Redis 标记死代码 | `PayOrderTask`、`OrderInfoMapper.selectWaitPaymentBefore`、`PayOrderRedisComponent`（删两方法）、`Constants`（删键） |
| 4 | V2 quote `FOR UPDATE` 无事务即释放、consume 后置于副作用 → 并发重复先落单后 409 | `claim-first`：`claim`（行锁+校验+占用短事务）在建单副作用前；失败 `release` 逆向释放 | `OrderQuoteService.claim/release`、`OrderInfoServiceImpl.createConfirmed`、`prepareOrder` 支持 presetPayOrderId |
| 5 | 幂等账本"独立事务"声明失效（REQUIRED 加入外层事务，秒杀入口回滚吞留痕） | `insertProcessing`/`markFailed` 走 REQUIRES_NEW；`markCompleted` 保持参与调用方事务（防假成功）；mapper/事务管理器改构造器注入 | `OrderRequestIdempotencyService` |
| 6 | Mock 渠道 `closeOrder` 缺意图抛错 → 关单消费者无限重投；`queryOrder` 缺意图打断整批 | 缺意图：closeOrder 幂等视为已关；queryOrder 返回 null | `PayChannel4Mock.closeOrder/queryOrder` |
| 7 | order_info/order_item/user_coupon/pay_trade_record/product_info 核心查询列零二级索引 | 4 个 Flyway 迁移补 14 个索引，全部 INPLACE+LOCK=NONE 在线 DDL | order `V5` / pay `V4` / coupon `V2` / product `V3` |

**行为变更（显式）**：秒杀 `@Transactional` 入口下命令失败后，同幂等键重放从"凭空重新执行"
变为 409 回放失败消息（与 V2 路径既有契约一致）；该入口的外层事务将在批次二移除。

## 配置 / 数据：启用与回滚说明

- **新增可配置项**（均有默认值，无需配置即可用）：`smartlect.pay.poll-min-age-seconds`
  （默认 180）、`smartlect.pay.poll-batch-size`（默认 200）。
- **数据库迁移（前向）**：order V5 / pay V4 / coupon V2 / product V3 共 14 个二级索引，
  MySQL 8 `ALGORITHM=INPLACE, LOCK=NONE` 在线创建不锁表；线上大表建议低峰执行。
  **回滚**：索引不承载约束，可按需 `DROP INDEX`（见各 V 文件头部说明）；Flyway 无 down
  脚本，代码回滚 = 回退上一发布版本（索引保留无害）。
- **删除的配置/键**：Redis 键 `smartlect:pay:trade:initiated:*`（死代码，无需清理，TTL 1 天
  自然过期）；`Constants.REDIS_KEY_PAY_TRADE_INITIATED` 常量删除。
