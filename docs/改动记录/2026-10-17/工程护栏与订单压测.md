# 工程护栏与订单压测

## 需求

把“服务边界”和“低并发交易回归”变成可重复门禁：ArchUnit 检查 API 契约/网关不反向依赖实现，Maven Enforcer 禁止 app 之间互相依赖；订单压测在本地 10/20 VU 记录原始 JSON，不把本地数字当生产容量。

## 变更

- 父 POM 引入 `archunit-junit5 1.3.0`：
  - `smartlect-gateway` 的 `GatewayArchitectureTest`：网关不得依赖 `controller/biz/mappers/service/task`。
  - `smartlect-order` 的 `OrderArchitectureTest`：`com.smartlect.api..` 不得依赖任何服务的 `controller/biz/mappers/state/component/task`。
- 父 POM 增加 `maven-enforcer-plugin`（3.5.0）`bannedDependencies`：禁止 9 个 app 构件互相依赖，只允许 `*-api` 与 `smartlect-common`。
- 新增订单压测证据 `docs/verification/order-load.md` 与 `eval/verification/2026-10-17/order-load/*.json`；README 已知边界更新为本地 10/20 VU 数据。
- 压测中发现 `/internal/product/listOnSaleProductIds` 全量返回 8.7 万条在售 ID：10 个并发夹具下打满商品服务 Hikari 4 连接池并触发堆内存压力，首轮 loadgen 无效。给内部端点加可选 `productIdPrefix` 过滤（`productId like %prefix%`），demo/loadgen 只取 `910000000000` 演示目录，避免为 20 个 SKU 拉全量；Dubbo 无参契约保留。
- `xxljob_setup.py` 增加 `payDailyReconcile`、`hotStockReconcile` 两个任务（16→18），README 运维入口补订单状态历史接口。

## 验证

- `mvn validate`：Enforcer 通过（含全部 app 模块）。
- `OrderArchitectureTest`、`GatewayArchitectureTest`：通过。
- 订单压测四轮 0 业务错误、0 传输层错误；20 VU 热点库存轮库存 20000→19728 = 272 单，守恒；hot on/off 差异在噪声内，详见 `docs/verification/order-load.md`。
- 全仓单测 516/516（0 failure / 0 error）；最终集成档 9 个 IT 类 / 45 个测试（1 个按条件跳过）BUILD SUCCESS；覆盖率汇总 38.7%（基线已抬到 0.3868）。证据：`eval/verification/2026-10-17/java-backend-convergence/`。
