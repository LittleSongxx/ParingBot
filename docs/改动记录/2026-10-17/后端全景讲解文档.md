### 文档结构（19 章，按「根约束 → 因果链」组织，非模块清单）

序（全貌 / 根约束 / 贯穿案例）→ 读链路（网关 / 商品·缓存·搜索 / 购物车·结算）→
写链路核心（下单五阶段 / 库存 / 幂等账本 / Outbox / 状态机与锁 / 超时关单与 24h 墙 / 支付与退款 / 优惠券）→
横切（身份与权限 / 五层防线 / 运维与门禁）→ 收尾（已知边界与接缝 / 一句话串完 + 反向索引表）。

**根约束**：一次成交要写 5 个库（订单 / 库存 / 券 / 支付单 / 地址），而没有任何一个事务能覆盖它们——
文档中每个机制都由它逐层推出（本地事务 + Outbox → 兜底扫描 → 消费幂等 → 请求幂等账本 → 对账哨兵；
条件更新防超卖 → 幂等回补 → 状态机 CAS + 支付单锁 → 延迟消息与驻留）。

**贯穿案例（真实种子数据）**：演示买家 `shopper@smartlect.demo` 买
`product_id=350000232815799`（索尼 WH-1000XX 十周年典藏版，SKU 白金色/WH-1000XX/标准，单价 ¥4169.00）1 件，
用「默认店体验秒杀券」（无门槛 ¥5），实付 ¥4164.00。商品、SKU、券、金额均来自仓库种子文件
（`backend/data/02_catalog_seed.sql`、`scripts/seed_store_playbook.py`）；**单号为讲解编造**（格式真实、数字示意），
文档在案例卡里已明示这一点。
