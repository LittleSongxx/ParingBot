# 支付对账与订单状态日志

## 需求

把 mock 支付从“内部令牌即可触发”加固到签名 + 防重放 + 渠道流水对账；同时让订单状态变化有可追溯的只追加历史，而不是只留最后状态。

## 变更

### Mock 支付签名

- 新增 `MockPaymentSignatureVerifier`：HMAC-SHA256，规范化字符串为 `POST\n/internal/pay/mock/complete\n<payOrderId>\n<amountCents>\n<timestamp>\n<nonce>`；时间窗默认 300 秒，nonce `[A-Za-z0-9_-]{8,64}` 在 Redis SETNX 防重放（TTL ≥ 600 秒）。
- `MockPaymentController#complete` 校验 `X-Mock-Pay-Timestamp/Nonce/Signature`，缺头/篡改/过期 401，重放 409；签名校验在委托身份与业务校验之前。
- 密钥：`SMARTLECT_MOCK_PAY_SECRET`（本地由 bootstrap 生成 32 字节随机值）；生产 profile 或 `smartlect.production-ready=true` 时若仍是开发默认值/长度不足 32，启动失败。
- 同步更新 `assistant` 的 CommerceClient、`scripts/demo.py`、`seed_store_playbook.py`、`scripts/loadtest/loadgen.py`；签名头由 Python `pay_signature.sign_complete` 生成。
- 演示/压测调用补委托用户头：`demo.py` 与 seed 的 complete 调用此前没有 session，实际会被 401 拒绝（本轮实测发现并修复）。

### 渠道流水与日对账

- pay V5 `pay_mock_channel_ledger`：`event_id` 唯一（`complete:<payOrderId>` / `refund:<refundOrderId>`），记录事件类型、支付单、退款单、金额、状态；V5 同步回填历史支付/退款，避免首次对账把旧数据全报成差异。
- `PayMockChannelLedgerService` 写入用 `insert ignore`，重放吸收；`PayChannel4Mock.completePayment/refund` 在支付/退款事务内写流水。
- `PayDailyReconcileTask`（`@XxlJob("payDailyReconcile")`）：对比业务表与流水，输出 `smartlect_pay_reconcile_diff_total{type}` 与日志，**不自动改账**；调度 `0 10 3 * * ?`。

### 订单状态历史

- order V7 `order_status_log`：订单号、支付单号、from/to、事件、操作者、时间；索引按订单/支付单。
- `OrderStateMachine.transition` CAS 成功后同事务写日志（幂等重入不写、0 行不写）；`transitionPayOrder` 先取受影响订单再逐单写；下单创建写 `null → WAIT_PAYMENT / CREATE`，秒杀建单同样写。
- 管理端只读接口 `GET /admin-api/order/{orderId}/statusLog`（服务内 `GET /admin/order/{orderId}/statusLog`），gallery 读默认允许。

### 顺带修复

- `PayInfoDTO` 未实现 `Serializable`，Dubbo 严格序列化下 `getPayUrl` 响应被丢弃，订单返回的 `payInfo/orderId` 为 null；补 `Serializable` 后 demo 的取消/退款链路恢复。该问题在签名联调时暴露，属于支付表单链路的真实回归。

## 未完成/边界

- 没有接真实渠道、清算/结算/资金账本；mock 支付不能当生产支付。
- 对账只报告差异，不自动修账；上线前历史回填只覆盖 `pay_channel='mock'` 的支付/退款。
- 状态历史只覆盖走状态机的路径；支付渠道兜底改 `pay_channel` 不写状态日志，因为状态未变。
- `xxljob_setup.py` 任务数从 16 增至 18（新增 `payDailyReconcile` 与 `hotStockReconcile`），需在部署环境重新执行登记。
