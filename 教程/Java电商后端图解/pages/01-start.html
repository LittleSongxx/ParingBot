商Smartlect 图解

01 · 项目速览

Smartlect 是一家「真的能买东西」的单店：C 端商城 + 商家后台，Java 微服务后端 9 个服务、8 个独立数据库。本图解只讲 Java 电商后端。

🎯 根约束（先记住这一句） 跨服务的每一步写操作，都必须自带幂等 + 自带补偿 —— 因为项目在 ADR-0006 里放弃了 Seata 分布式事务（全库 0 个 @GlobalTransactional、0 个 seata 依赖）。 后面每一章的机制，都是这句话的推论。ADR-0006

刻意不做什么（比做了什么更能解释设计）

  • 不上分布式事务框架 —— Seata 已整套移除，跨服务一致靠幂等键 + 条件更新 + Outbox + 对账（第 12 章展开）。
  • 服务间不用 REST 调用 —— 全库 0 个 @FeignClient，同步调用清一色 Dubbo；HTTP /internal/** 只留给 AI 导购与运维。
  • 价格、库存不进缓存、不进向量 —— 商品缓存里库存字段清零，读缓存后实时回查 stock；「交易事实以查询时点为准」。ProductCacheService.java:20
  • 购物车不用 Redis —— 就一张 product_cart 表。
  • 支付不接真渠道 —— PayChannelEnum 只有 MOCK，无真实资金。
  • 秒杀不为所有请求服务 —— 限流和 Redis 预占把绝大多数请求挡在 DB 之前（第 10 章）。
