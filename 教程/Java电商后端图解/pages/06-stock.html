06 · 库存扣减

没有预占字段、没有 Redis 扣减——一张两列的表 + 一条带 WHERE 条件的 UPDATE + 一张幂等台账，把「不超卖」和「不重复扣」同时解决。

两件必须同时成立的事

  • 不超卖：扣减必须是「检查 + 扣」一步完成 → 条件更新。
  • 不重复扣：Dubbo 超时重试、Outbox 重放都可能让同一单扣两次 → 先抢幂等键。

要点

  • 幂等键的生命周期：扣减时抢键 → 回补时删键。键在 = 「这单扣过」；键删 = 允许重新扣。回补自己另有 SHA-256 键防重。
  • TreeMap 字典序：所有调用方以同一顺序拿行锁，两单并发扣同一批 SKU 也不会交叉死锁。
  • 库存从不进缓存、从不进 ES——全站只有 stock 服务能改它，读它的地方（详情页、购物车、下单预检）全部现查。
  • 回补失败不会丢：order 侧 remoteCompensateRecorder 落补偿台账，人工/任务可重放（ch.12）。
🧺 案例进度 shopper 的单进入 stock：抢键 order-deduct:PO-DEMO 成功 → iPhone 银色256G 一条 UPDATE，564 → 563。若此刻另一请求也买最后一件，双方行锁排队，后到者 affected=0 → 「库存不足」。
