09 · 订单状态机

9 个状态、10 种事件，合法迁移全部写死在一张表里；每次迁移都是一条「带旧状态条件的 CAS UPDATE」——并发抢状态、消息重放，都伤不到它。

迁移的实现：CAS，不是 if-else

-- 每次迁移 = 一条带旧状态条件的 UPDATE（OrderStateMachine.transition）
UPDATE order_info
SET order_status = <目标>
WHERE order_id = ? AND order_status = <期望旧状态>;
-- rows = 1 → 迁移成功
-- rows = 0 → 两种可能：
--   ① 目标态 == 当前态：视为幂等重放，读比对后安全返回
--   ② 其他：非法流转 / 并发被别人抢先 → 抛异常
-- 按 payOrderId 整组迁移（transitionPayOrder）：一次结算的多个子单同生共死
