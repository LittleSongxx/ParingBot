商Smartlect 图解

04 · 商品与搜索

商品在 MySQL（权威），搜索靠 ES（只出 ID），两者之间用 Canal 从 binlog 增量同步——查询链路不依赖同步链路，ES 挂了自动回退 SQL LIKE。

数据模型：一台 iPhone 怎么存

搜索链路：ES 只做一件事——筛出 ID

⚠️ 反直觉的一处 索引里明明装了 IK 分词器（ik_max_word），但搜索谓词不是分词 match，而是 wildcard 通配——为了和 SQL LIKE '%kw%' 逐字等价（曾改成分词检索、因破坏「逐字等价」语义被回退）。IK 只用于 text 快照字段的存储分词。价格、库存不进索引。ProductIndexService.java:211

写链路：Canal 把 MySQL 的变更搬进 ES

详情页多级缓存：静态进缓存，库存永远现查

🧺 案例进度 shopper 在搜索框输入「iPhone」→ wildcard 命中 iPhone 17 Pro Max → 详情页：名称/图/¥8999–16999 来自缓存静态快照，SKU「银色 256G ¥8999」旁的库存 564 是刚从 stock 服务查的。下一步：加购（ch.05）。
