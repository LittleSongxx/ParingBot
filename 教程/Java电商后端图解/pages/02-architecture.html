商Smartlect 图解

02 · 总体架构

浏览器 → Nginx → 网关 → 8 个业务服务 → 中间件。同步调用全走 Dubbo（Nacos 注册），异步事件全走 RocketMQ，每个服务一个 MySQL 库。

服务间怎么调用：纯 Dubbo

  • 同步调用全部是 @DubboReference → @DubboService，注册中心 Nacos；全库 0 个 @FeignClient。
  • 代码里大量 XxxFeignSupport 类名是历史遗留——里面装的是 Dubbo 引用，别被骗。ProductFeignSupport.java:46
  • 每个 provider 同时暴露 Dubbo 接口和 HTTP /internal/**（X-Internal-Token 保护），双通道共用同一 Service 层——HTTP 通道留给 AI 导购与运维。
💡 这张图看不到的事 Dubbo 只是「同步询问」的通道；真正把支付成功、超时关单、退款串起来的，是 RocketMQ 里的事件与定时消息（紫色，见 ch.08/09/11）。同步图里安静的 pay 和 stock，在异步图里非常忙。
